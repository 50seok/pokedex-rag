# PRD — 관동 도감 (Kanto Pokédex RAG)

> 최종 갱신: 2026-09-03 · 상태: 설계 확정, 구현 착수 전

## 1. 왜 만드는가

**1차 목적 — 포트폴리오.** 면접에서 "학원 프로젝트 말고 최근에 만든 게 있냐"는 질문에 링크 하나로 답할 수 있는 결과물. 학원 프로젝트(Spring Boot CRUD)와 겹치지 않게 **RAG·LLM 연동**이라는 축을 하나 더 얹는다.

**2차 목적 — 실제 쓸모.** 관동 지방 정보를 찾을 때 위키를 뒤지는 대신 자연어로 물어보면 답이 나오고, **근거 문서를 함께 보여준다**.

**성공 기준**
- 면접관이 URL을 눌러 30초 안에 질문 → 답변까지 경험할 수 있다
- "어떻게 만들었냐" 질문에 청킹·임베딩·검색·프롬프트 각 단계를 근거를 들어 설명할 수 있다
- 답변에 항상 출처가 붙어 "지어낸 답이 아니다"를 증명할 수 있다

## 2. 범위

**만든다**
- 관동(1세대) 한정: 포켓몬 151 / 마을 약 10 / 도장 8
- 자연어 질의응답 (챗 UI) + 출처 표시
- 정적 도감 페이지 (포켓몬·마을·도장 상세)
- 출처 클릭 시 해당 도감 페이지로 이동

**안 만든다** — 스코프만 키우고 목적에 기여하지 않음
- 로그인·회원가입 (질문에 인증이 필요 없음)
- 배틀 시뮬레이터, 팀 빌더
- 관동 외 지역 (데이터 파이프라인은 확장 가능하게 두되 이번엔 넣지 않음)
- 이미지 업로드, 관리자 화면, 댓글

## 3. 사용자 시나리오

1. **지역 질문** — "관동에 물타입 도장 있어?" → 세이지시티 체육관과 관장 정보 + 출처 칩
2. **포켓몬 질문** — "피카츄 어디서 잡아?" → 등장 지역 + 도감 설명 + 출처 칩
3. **둘러보기** — 챗 없이 도감 목록에서 마을을 골라 상세 정보를 읽는다

## 4. 기술 스택 결정

| 영역 | 선택 | 이유 | 기각한 대안 |
|---|---|---|---|
| 언어·런타임 | Java 21 (LTS) | 학원 스택, 백엔드 포지션 어필 축 | Python — RAG는 쉬우나 지원 포지션과 어긋남 |
| 프레임워크 | Spring Boot 3.x | 위와 동일 | — |
| 빌드 | Gradle | 학원 프로젝트와 동일 | Maven |
| 프론트 | Thymeleaf + 바닐라 JS | 배포 대상 1개로 유지, 챗은 `fetch`로 충분 | React — 배포 2곳·CORS·빌드 파이프라인 추가 |
| DB | PostgreSQL 16 + pgvector | 도감 데이터(JPA)와 벡터 검색을 DB 하나로 해결 | Chroma — 관계형 DB가 어차피 필요해 인프라 2개가 됨 |
| LLM | Gemini API 무료 티어 | 응답 1~3초, 클라우드 배포 가능 | Ollama 로컬 — 무료 클라우드에 못 올리고 GPU 경합 시 30초~3분 |
| 임베딩 | Gemini 임베딩 API | LLM과 API 키 하나로 통일 | ko-sroberta(sentence-transformers) — 파이썬 전용이라 매 요청 파이썬 경유 필요 |
| RAG 구현 | 직접 구현 | 청킹·검색·프롬프트를 설명할 수 있어야 포트폴리오 가치가 생김 | Spring AI — 코드는 줄지만 내부를 설명 못 하면 어필이 사라짐 |
| 앱 호스팅 | Render 무료 | GitHub 푸시 자동 배포, 설정 최소 | AWS EC2 — 인지도는 높으나 세팅 부담 + 12개월 후 과금 |
| DB 호스팅 | Neon 무료 | 영구 무료, pgvector 지원 | Render 무료 DB — **30일 후 삭제**되어 사용 불가 |

## 5. 시스템 구조

```
[브라우저]
   │ 질문 (fetch POST /api/chat)
   ▼
[Spring Boot]
   ├─ 1. 질문 임베딩          → Gemini 임베딩 API
   ├─ 2. 유사 문서 top-5 검색  → Neon PostgreSQL (pgvector)
   ├─ 3. 프롬프트 조립 (검색된 문서 + 질문)
   ├─ 4. 답변 생성            → Gemini API
   └─ 5. 답변 + 출처 목록 반환
   ▼
[브라우저] 답변 표시 + 출처 칩 (클릭 → /pokemon/{id}, /town/{id})
```

도감 페이지(`/pokemon/**`, `/town/**`, `/gym/**`)는 벡터를 거치지 않고 JPA로 직접 조회한다.

## 6. 데이터 소스

**검증 완료 (2026-09-03, PokeAPI 실제 호출로 확인)**

| 대상 | 소스 | 한국어 | 수집 방식 |
|---|---|---|---|
| 포켓몬 151 | PokeAPI `/pokemon-species/{id}`, `/pokemon/{id}` | ✅ 이름·분류·도감설명(종당 최대 12개) 확인 | 스크립트 자동 수집 |
| 마을 약 10 | 없음 | ❌ **한국어 이름조차 없음** (`pallet-town` → ko 필드 비어 있음) | **수동 작성** |
| 도장 8 | 없음 | ❌ 관장·배지·타입 정보 자체가 PokeAPI에 없음 | **수동 작성** |

마을·도장은 18건뿐이라 스크래핑보다 직접 쓰는 게 빠르고, 저작권 문제도 피할 수 있다 (사실 정보를 자기 문장으로 정리). `data/kanto-towns.json`, `data/kanto-gyms.json`으로 레포에 커밋한다.

## 7. 데이터 모델

```
pokemon   (id, name_ko, genus_ko, types, hp, attack, defense, speed, sprite_url, flavor_ko)
town      (id, name_ko, name_en, description, notable_places)
gym       (id, town_id, leader_ko, type, badge_ko, description)
document  (id, source_type, source_id, title, content, embedding vector(768))
```

- `document`가 RAG 검색 대상. `source_type`/`source_id`로 원본 행을 가리켜 **출처 링크**를 만든다
- 벡터 검색은 `JdbcTemplate` 네이티브 쿼리(`embedding <=> ?` 코사인 거리), 나머지는 JPA
  → Spring Data JPA가 vector 타입을 다루지 못해서 이 지점만 분리한다
- **`type`/`types`는 데이터·백엔드 전체에서 PokeAPI 영문 slug(`grass`, `rock`...)를 그대로 쓴다.** 18종류뿐인 값을 151+8개 레코드마다 한국어로 중복 저장하지 않고, 한국어 라벨은 M4에서 Thymeleaf 템플릿단의 매핑 테이블(`Map<String,String>` 18개) 하나로 변환한다. 그 외 `name`/`genus`/`flavorText`/`leader`/`badge`/`townName`은 애초에 한국어 값만 저장하므로(영문 대응값 없음) 별도 조치 불필요

## 8. RAG 파이프라인

**청킹** — 하지 않는다. 문서 1건이 200~500자로 짧아 자를 이유가 없다.
- 포켓몬 1마리 = 1문서 (이름·타입·분류·종족값·도감설명 결합) → 151건
- 마을 1개 = 1문서 → 약 10건
- 도장 1개 = 1문서 → 8건
- **총 약 170문서**

**임베딩** — 차원 768로 축소 요청 (3072는 170건 규모에 저장·연산 낭비). 인제스트 1회 + 질문마다 1회.

**검색** — 코사인 유사도 top-5. 170건 규모라 인덱스 없이 순차 스캔으로 충분하며, HNSW 인덱스는 넣지 않는다.

**프롬프트** — 검색된 문서만 근거로 쓰고, 문서에 없으면 "정보가 없다"고 답하도록 지시한다 (할루시네이션 억제).

**출처** — 응답에 `sources: [{type, id, title}]`을 포함해 UI에 칩으로 표시하고 도감 페이지로 링크한다.

## 9. 환경 설정

| 변수 | 용도 |
|---|---|
| `GEMINI_API_KEY` | LLM·임베딩 공용 |
| `DATABASE_URL` | 로컬은 Docker Compose, 프로덕션은 Neon |
| `SPRING_PROFILES_ACTIVE` | `local` / `prod` |

- 로컬: `docker-compose.yml`로 `pgvector/pgvector:pg16` 컨테이너 구동
- 키는 `.env`·환경변수로만 주입, 레포에 커밋 금지 (`.gitignore` 등록)

## 10. 배포

Docker 이미지 → Render 무료 Web Service, DB는 Neon 무료.

**제약과 대응**

| 제약 | 영향 | 대응 |
|---|---|---|
| Render 512MB RAM | Spring Boot 기동 실패 가능 | `-Xmx320m` 등 JVM 튜닝, 의존성 최소화 |
| Render 15분 유휴 시 슬립 (콜드스타트 약 1분) | 면접관이 링크를 눌렀을 때 1분 대기 | 외부 크론(UptimeRobot 등)으로 10분 간격 핑. 월 744시간 < 무료 750시간 한도 |
| Neon 5분 유휴 시 scale-to-zero | 첫 쿼리 지연 | 위 핑이 DB까지 건드리도록 헬스체크 구성 |
| Gemini 무료 1,500 요청/일 | 데모용으로는 충분 | 429 응답 시 사용자에게 안내 메시지 처리 |

## 11. 리스크

1. **Gemini 무료 티어는 입력 데이터가 학습에 사용될 수 있음** — 공개된 포켓몬 정보만 다루므로 실질 문제 없음
2. **포켓몬 IP 저작권** — 개인 비영리 포트폴리오, 상업적 이용 없음. 스프라이트는 PokeAPI 제공 URL을 링크로만 사용하고 재배포하지 않는다. README에 명시
3. **한국어 임베딩 품질** — Gemini 임베딩의 한국어 성능이 ko-sroberta보다 낮을 가능성. M2 완료 시점에 실제 질문 10개로 검색 정확도를 눈으로 확인하고, 나쁘면 그때 대안 검토

## 12. 마일스톤

| 단계 | 내용 | 완료 기준 (사용자가 직접 확인) |
|---|---|---|
| M1 | 데이터 수집 — PokeAPI 스크립트 + 마을·도장 수동 작성 | JSON 파일에 151/10/8건이 한국어로 들어있다 |
| M2 | DB·인제스트 — 스키마, pgvector, 임베딩 적재 | 질문 10개로 검색해 관련 문서가 상위에 뜬다 |
| M3 | RAG API — 검색·프롬프트·Gemini·출처 | `/api/chat` 호출 시 답변과 출처가 돌아온다 |
| M4 | 화면 — 도감 페이지 + 챗 UI | 브라우저에서 질문하고 출처 칩을 눌러 이동된다 |
| M5 | 배포 — Docker, Render, Neon, 핑 | 공개 URL에서 M4와 동일하게 동작한다 |

## 13. 아직 확정하지 않은 것

- **Gemini 모델 ID** — 조사한 모델명의 출처가 신뢰도 낮은 2차 자료라 여기 박아두지 않는다. M3 착수 시 Google AI Studio 콘솔에서 무료 티어 모델 목록을 직접 확인하고 확정한다
- **Spring Boot 패치 버전** — 프로젝트 생성 시점의 최신 3.x
- **UptimeRobot 대안** — Render 약관상 핑이 문제되면 면접 직전 수동 웜업으로 대체
